# Переход с SQLite на MySQL

Сейчас плагин работает на SQLite: вся база — один файл `plugins/LogicTierPlugin/tierplugin.db`.
Код под MySQL уже есть (`storage/SqlDialect.java`), переход — это настройка, без правок кода.

> На реальном MySQL код пока не прогонялся: тесты и сервер проверены только на SQLite.
> Перед переходом на проде стоит один раз проверить на тестовой базе.

## Когда переходить

| Ситуация | Что выбрать |
|---|---|
| Один сервер, до нескольких сотен игроков | SQLite, ничего не менять |
| Несколько серверов (BungeeCord/Velocity) с общим рейтингом | MySQL |
| Сайт, Discord-бот или веб-топ должны читать рейтинг | MySQL |
| Хостинг не даёт писать файлы в папку плагина или часто пересоздаёт контейнер | MySQL |

## Где держать базу

Главное правило: **база должна быть как можно ближе к серверу Minecraft**, в идеале на той же машине
или в том же дата-центре. Главный поток сервера на базу не ждёт (запись идёт в отдельном потоке), но
от задержки зависит, как быстро игрок увидит результат боя и ответ `/tier`.

1. **MySQL от игрового хостинга** (лучший вариант для «условного хостинга»).
   У большинства игровых хостингов на панели Pterodactyl есть вкладка **Databases** — там одной
   кнопкой создаётся база, и панель сразу показывает host, port, имя базы, пользователя и пароль.
   База находится в той же сети, что и сервер, бэкапы обычно делает хостинг.
2. **Свой VPS**: MySQL ставится на ту же машину, что и сервер Minecraft (`host: 127.0.0.1`).
   Порт 3306 наружу не открывать.
3. **Управляемая облачная база** (Aiven, DigitalOcean, Яндекс Cloud и т. п.).
   Подходит, если серверов несколько или нужен доступ с сайта. Выбирайте регион рядом с сервером и
   включайте SSL.

Чего избегать: бесплатных удалённых MySQL на другом континенте и баз, открытых в интернет с паролем
`root` без ограничения по IP.

## Шаги

### 1. Создать базу и пользователя

На хостинге с панелью это делает кнопка «Create database». На своём сервере:

```sql
CREATE DATABASE tierplugin CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'tierplugin'@'localhost' IDENTIFIED BY 'длинный-случайный-пароль';
GRANT ALL PRIVILEGES ON tierplugin.* TO 'tierplugin'@'localhost';
```

Если MySQL на другой машине, вместо `'localhost'` указать IP сервера Minecraft (не `'%'`).

### 2. Прописать подключение в `plugins/LogicTierPlugin/config.yml`

```yaml
database:
  type: mysql
  host: 127.0.0.1        # или адрес, который выдала панель хостинга
  port: 3306
  name: tierplugin
  user: tierplugin
  password: "длинный-случайный-пароль"
  pool-size: 5
```

Драйвер MySQL уже входит в Paper, ставить ничего не нужно.

### 3. Перезапустить сервер и проверить

- В консоли: `[LogicTierPlugin] Database ready (MYSQL).` Таблицы создаются сами.
- Провести бой (`/tieradmin fight ...`), посмотреть `/tier` и `/tieradmin stats`.
- Перезапустить сервер — цифры должны остаться.

Если в консоли `Failed to initialise database`, плагин выключится сам. Причины почти всегда в
адресе, пароле или в том, что пользователю не разрешено подключаться с IP сервера.

## Перенос данных из SQLite

Автоматического переноса пока нет: после переключения MySQL начинается с пустой базы, а файл
`tierplugin.db` остаётся на месте. Если нужно сохранить рейтинг, перенос делается отдельной
командой (`/tieradmin migrate`, пока не реализована) или скриптом по таблицам
`players`, `ratings`, `matches`, `metrics`.

## Особенности и ограничения

- Все запросы идут в одном потоке базы по очереди, поэтому `pool-size` больше 1 пока не ускоряет работу.
- В адресе подключения стоит `useSSL=false` — нормально для localhost и локальной сети.
  Для удалённой облачной базы SSL нужно включить (правка в `storage/Database.java`).
- MySQL 8.0.20+ может писать в лог предупреждение об устаревшем `VALUES()` в `ON DUPLICATE KEY UPDATE`.
  Это не ошибка; синтаксис оставлен ради совместимости с MariaDB.
- Несколько серверов на одной базе пока не поддерживаются полностью: дневной лимит матчей на пару
  может посчитаться дважды, если два сервера записывают матч одной пары одновременно.

## Бэкапы

- **SQLite:** остановить сервер и скопировать `tierplugin.db`. Копировать файл при работающем
  сервере не стоит — копия может оказаться битой.
- **MySQL:** `mysqldump tierplugin > tierplugin-ГГГГ-ММ-ДД.sql` по расписанию или бэкапы панели хостинга.
